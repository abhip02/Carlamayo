# Input-contract and control-delivery investigation — round 4

Branch: `experiment/driving-input-contract`, starting checkpoint `27935e2`.
Evidence root: `outputs/driving-investigation-4/`.
Previous results: [round 3](RESULTS_ROUND3.md).

This round tests acknowledged control delivery in the failed green scenario and
checks input preprocessing and numerical inference assumptions. Production
controller/configuration, normal launchers, model weights and external model
sources are unchanged. Experiments remain opt-in and reversible.

## Independent input checks

- **Image preprocessing:** `input_contract.py` compares NVIDIA's processor defaults
  against the adapter's explicit pixel limits on saved green frame 022. All four
  outputs (`input_ids`, `attention_mask`, `pixel_values`, `image_grid_thw`) are
  bitwise identical. Both use grid `[1, 20, 36]` per image. The differing minimum
  pixel limits do not change this actual input (`processor-contract.json`).
- **Pose history:** reconstruct seven saved histories from CSV world poses using
  CARLA's own transformation matrices, then independently reflect y and shift to
  the rear axle. Maximum position discrepancy is 0.00001293 m and rotation-matrix
  discrepancy is 9.41e-8 (`history-contract.json`). This checks the saved histories,
  including turned states; it does not establish camera calibration accuracy.
- Source inspection confirms RGB conversion, camera ordering `[0,1,2,6]`, four
  image frames at 0.1 s, sixteen pose samples, and explicit `model.eval()`.
- The first CPU-only processor-check attempt incorrectly tried AutoTokenizer on
  the model checkpoint and failed before processing images. The corrected script
  uses the reference configuration's tokenizer construction. No dependencies were
  changed and no model weights were loaded for these checks.

## Lens and inference hypotheses

`camera_projection: calibrated_fisheye` refines the existing equidistant remap
with principal points and fitted Kannala–Brandt distortion coefficients. Values
come from [CARLA's public rig](https://github.com/carla-simulator/carla/blob/ue58-dev/PythonAPI/examples/av_stacks/alpamayo/alpamayo_rig.py),
retrieved 2026-10-29. That rig cites **Alpamayo 2** validation calibration; these
values initially lacked validation against our 1.5 checkpoint's inputs. It uses
the same saved wide pinhole renders and camera poses, so no new simulator version
or sensor is required.

Later in this round, calibration fetched from the actual **1.5 reference clip**
confirmed the same nominal rig poses, focal lengths and principal points. The
pose rotations match within 6e-8 and translations within 0.5 micrometres, before
the production front-camera body-clearance adjustment. The fitted KB inverse
maps differ from the dataset's native inverse polynomials by 0.013–0.648 source
pixels on average, with larger differences at extreme edges (up to 53 pixels).
Thus the nominal calibration source is now checked against this 1.5 example,
but the simulated sensor images still do not exactly reproduce its optics or
appearance. See `reference-calibration.json` and
`reference-calibration-comparison.json`.

Independent forward-projection equations verify inverse-map round trips below
0.00015 pixels. Source coverage exceeds 99.99% for all cameras; average source
pixel displacement versus the old projection is 6.4–10.2 pixels
(`lens-map-check.json`, `lens-comparison.jpg`). These are geometric checks, not
driving results.

Frozen-input variants preserve four native motion samples and motion seed 42:

`fixed_intent` supplies the complete assistant reasoning and trajectory-start
marker. Its reasoning is experimenter-supplied text, **not model perception or an
explanation generated by the model**. It does not edit the returned waypoints.
The red intent is used only on the already identified red-light test input.

The initial green `fixed_intent` test unnecessarily generated additional text
after the supplied marker: upstream's stopping rule detects newly generated
markers, whereas the cache mask uses the first marker, including one in the
prefix. This post-marker text was masked out of motion conditioning. The scoped
option now limits generation to one token, obtaining the completed prompt's
cache directly. A separate native/fixed-intent rerun on both green inputs
confirmed the same failure (`replay-green-intent-prefill/`). Exact source versions
are saved in each run's `source_snapshot/`.

`compare_replays.py` applies every variant to the same recorded previous plan,
with the original red stop cost where relevant. It reports every candidate's
target speed, path length, endpoint, route cost, and marker status. The best
available candidate is not necessarily an acceptable one.

Completed frozen comparisons: 14 green evaluations, 7 on a red held-stop frame,
14 on two actual red restart/malformed frames, 4 corrected green intent-prefill
checks, and 3 reference-clip evaluations: **42 inference calls**. Every native
baseline and repeat exactly reproduced the corresponding saved candidates.

Green remains a failure under every tested variant: the early selected target
remains below the 0.25 m/s stop threshold, and all later candidates remain far
off route. At frame 022, some *other* native candidates request movement, so the
continuity selector also matters; do not describe every early sample as stopped.
At frame 057, no sampled candidate supplies the requested straight route.

Reference motion attention changes individual waypoints by at most about 0.016 m
on these failures and does not repair them. Refined lenses and restricted views
can worsen red motion. Higher language temperature and completed stop intent
shorten the red predictions, but at frame 076 the completed-intent selected plan
still travels 5.13 m, with a 1–1.5 s target of 1.86 m/s while the car is already
moving at 2.11 m/s. Shortening alone is not proof of a correct stopping response.
The completed-intent change therefore receives a bounded live test below.

Red frame 065 was a held-stop control, not a restart: its native selected plan
already had target 0.101 m/s and path length 0.558 m. It was followed by the
actual malformed/restart inputs 067 and 076 rather than being presented as a
successful repair. Full arrays are in `green-contract-comparison.json`,
`green-intent-prefill-comparison.json`, `red-contract-comparison.json`, and
`red-restart-comparison.json`.

## Reference inference check

Using existing dataset access, streamed only the clip used by
[NVIDIA's example](https://github.com/NVlabs/alpamayo1.5/blob/36aeb4c5938cbc2eb2aed33b22434773da4ab639/src/alpamayo1_5/test_inference.py):
`030c760c-ae38-49aa-9ad8-f5650a545d26`, t0 = 5.1 s. Dataset revision is
`39414de6f0ab867238ad6a0299fcd18b26081b42`. No new weights, packages, or account
permissions were required. The raw native dataset images receive no CARLA lens
remapping. The same local BF16/SDPA sharded model and adapter use the reference
seed 42, language sampling defaults, and ten diffusion steps.

Single-sample average displacement error over the 6.4 s future is **0.379 m**;
final displacement error is 2.197 m. Repetition is bitwise identical. Four native
samples have ADEs 1.023, 0.315, 0.521, and 0.392 m. Every generation contains its
trajectory marker, and none predicts reverse motion. The single sample passes
the example's 1 m mean-error sanity threshold (`reference-metrics.json`).

This is evidence that the local stack can produce coherent predictions on a
reference input. It does not prove CARLA compatibility, broadly validate the
model, or establish visual domain shift as the sole cause of the simulator
failures. It makes a general checkpoint-loading or inference-stack failure less
likely. The saved input is `reference_input.pt`; its options and exact sources
are in `reference-variants.json` and `replay-reference/`.

## Live validation

`capture-ack-green-43`: same common green settings as round 3, plus
`acknowledged_controls: true`; planned duration 12 s. Original controller values
are delivered in acknowledged CARLA command batches. Exact sources loaded by the
process were copied to `source_snapshot/` and hash-verified before further edits.

Completed: zero reported-control mismatches across 120 calls, but maximum lateral
deviation **15.095 m**, forward progress **32.649 m**, and final heading change
−111.16°. A near-stop occurred at 11.7 s after leaving the requested route; minimum
speed was 0.035 m/s. No collision. One selected generation lacked a marker at
10.9 s. All 120 consumed trajectories exactly match their selected native
candidates, and recorded snapshots match CSV frames and positions.

The run did avoid the earlier 2 s stop, reaching a minimum of 0.722 m/s before
resuming through the approach. This is not a successful crossing, and one live
comparison cannot attribute the changed behavior solely to control delivery.
Initial pose/history tensors are identical; raw image mean absolute difference
is 0.054 on the 0–255 scale (`initial-input-comparison.json`).

Artifacts: `ack-green-audit.json`, `control-delivery-comparison/`, the 12.1 s video
`control-delivery-comparison.mp4` (including t0), and
`capture-ack-green-43/000_verifai/overhead-h264.mp4`.

`capture-complete-red-43`: planned 8 s, same settings as round-3 common red 43,
with the single addition `complete_visual_stop_intent: true`. When the separate
visual question answers red/yellow, condition motion on a completed stop intent
instead of letting the language model continue that prefix. No simulator signal
state is fed into inference. Unknown/green retains native reasoning. The original
controller and native command delivery remain matched to the earlier red run.
Completed: stopped below 0.25 m/s at **2.0 s** and held through **8.0 s**, with
**no restart**. Maximum measured speed from 2.1 s onward was 0.00543 m/s; final
speed was effectively zero. Maximum lateral deviation was 0.060 m. No collision

The initial visual check answered unknown, followed by 15 red answers. All
recorded signal states were red. Native command delivery reported 13 mismatches;
seven after stopping involved steering only, with no brake mismatch anywhere.
All 80 consumed plans exactly match their selected native candidates, and
snapshot poses/frame IDs agree with the CSV. On red, the trajectory marker is
supplied by construction; marker presence is not evidence of repaired language
generation. Some unselected motion samples still propose movement.

This is an encouraging **single-seed hold test**, not a robust fix. The previous
red seed 43 restarted at 3.2 and 7.0 s; the new run did neither. Initial pose and

## Reproduction and final checks

The two live presets are `presets/acknowledged-green-43.json` and
`presets/completed-stop-red-43.json`. These preserve test settings, not recommended
production defaults. For example:

```bash
bash local/server.sh start
source local/env.sh
.venv/bin/python -m local.experiments.inference_probe capture \
  --config local/configs/demo.yaml --duration 8 --capture-frames 0 19 28 67 76 \
  --options local/experiments/presets/completed-stop-red-43.json \
  --output outputs/driving-investigation-4/my-red-recheck
bash local/server.sh stop
```

All existing 63 controller, adapter, pose-history and VerifAI tests passed.
The independent lens round-trip and history checks passed; native frozen-input
replays are exactly repeatable. The full run sources are hash-verified under
their `source_snapshot/` directories. Model-free/CPU checks did not share the
simulator with live rollouts, and model processes were sequential.

The simulator was restored to asynchronous mode, with zero sensors and zero
rollout vehicles remaining, then the owned container was stopped. No experiments
remain running. Production controller/configuration still match upstream
`4914558`; external model sources are clean.

The useful follow-up is to verify the completed stop-intent approach across seeds
and approach distances, while treating the unresolved green route failure as a
separate problem. The reference result and input audits support investigating
simulated appearance/scene interpretation and route conditioning next; they do
not establish a single root cause. No trajectory rewriting, target-speed floor,
signal-state oracle, or unsafe-plan fallback was added.
